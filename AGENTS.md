# AGENTS.md — gPower

Входной документ для любого LLM-агента, работающего с этим репозиторием. Читай его первым; остальную документацию — точечно по индексу ниже, чтобы не тратить контекст.

## Что это

gPower — мини-сервис поддержки пользователей на базе каталога из 876 упражнений: каталог с фильтрами и двуязычным поиском (RU/EN), универсальный ИИ-ассистент, RAG-поиск по документации каталога и подключение данных каталога через MCP.

Монорепо на npm workspaces: `apps/web` (Vue 3), `apps/server` (Fastify + RAG + LLM), `packages/catalog-core` (данные/поиск), `packages/mcp-catalog` (MCP-сервер).

## Команды

```bash
npm install                 # установка всех workspaces
npm run dev                 # web :5174 + api :3000 + mcp :3001
npm run dev:api             # только API
npm run dev:web             # только web
npm run dev:mcp             # только MCP-сервер
npm run index               # пересборка RAG-индекса (нужна Ollama; ~18 мин)
npm run summaries           # генерация RU/EN-резюме упражнений (нужен DEEPSEEK_API_KEY)
npm run build               # прод-сборка web
```

Требования: Node.js 22+ (используется встроенный `node:sqlite`), запущенная Ollama с `qwen3-embedding:0.6b`, `DEEPSEEK_API_KEY` в `.env` (шаблон — `.env.example`).

## Инварианты (нарушать нельзя)

1. **Не коммитить `.env`** и любые секреты. `.env` уже в `.gitignore` — не добавляй его в git.
2. **Не изменять `free-exercise-db/`** (внешний клон датасета) — он обновляется через `git pull`. Любые дополнения данных — только в `data-aug/`.
3. **`data/` (SQLite-база и RAG-индекс) не в git** — пересобирается командой `npm run index`.
4. **PK виртуальной таблицы `vec_docs` принимает только BigInt** — вставляй `BigInt(rowid)`, иначе `Only integers are allowed for primary key values`.
5. **`sqlite-vec` — CJS-пакет**: подключается через `createRequire(import.meta.url)`, ESM-`import` по умолчанию не работает.
6. **Ответы ассистента не содержат markdown-разметки** — `**`/`__` заменяются на `"` санитайзером; не убирай его.
7. **Не «фиксить» `v-model` на объекте из `reactive`** в шаблонах: это ломается (см. `docs/pitfalls.md`); используй `:modelValue` + `@update:modelValue`.
8. **Правя контракт — правь доку**: изменение эндпоинта, схемы БД, MCP-инструмента или SSE-события обязано сопровождаться обновлением соответствующего файла в `docs/`.

## Правила работы (SDD)

1. Новая фича — сначала **спека** по шаблону `docs/sdd/templates/feature-spec.md` (цель, контракты, критерии приёмки), затем план и задачи. Не начинай писать код без критериев приёмки.
2. **Источник истины**: продукт — `docs/SPEC.md`; система — `docs/architecture.md` + `docs/api.md` + `docs/data.md` + `docs/mcp.md`. Если код расходится с документацией — не угадывай: сообщи о расхождении.
3. Не расширяй объём задач сверх спеки. Не додумывай контракты — они описаны таблицами, используй их дословно.
4. **Определение готовности**: код компилируется (`npm run build` для web), изменение проверено способом из раздела «Проверка» спеки (для API — `curl`, см. `docs/api.md`), документация обновлена.

## Проверки (шпаргалка)

```bash
npm run build                                  # web собирается
curl http://localhost:3000/api/health          # {"status":"ok","exercises":876}
curl http://localhost:3000/api/filters         # значения фильтров с RU-подписями
```

Для запросов, содержащих кириллицу, используй `curl --data-binary @file.json` (файл в UTF-8) — иначе PowerShell исказит тело запроса (см. `docs/pitfalls.md`).

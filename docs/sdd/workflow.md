# workflow.md — разработка по спекам (SDD)

Процесс для изменений проекта, оптимизированный под работу с LLM: сначала письменная спецификация с критериями приёмки, затем план, затем задачи. Код без спеки не пишем.

## Артефакты

```
docs/
├── SPEC.md                 # продуктовая истина (обновляется при изменении продукта)
├── sdd/
│   ├── workflow.md         # этот файл
│   ├── templates/          # feature-spec.md, plan.md, tasks.md
│   └── features/           # активные фичи: <NNNN-slug>/{spec,plan,tasks}.md
```

Фича заводится как каталог `docs/sdd/features/<NNNN-slug>/` (NNNN — порядковый номер) с тремя файлами по шаблонам. После завершения фича остаётся как история решений; продуктовые изменения переносятся в `docs/SPEC.md`, системные — в `docs/architecture.md` и контракты.

## Шаги

1. **Specify.** Заполни `spec.md`: цель, пользовательская ценность, контракты (эндпоинты/схемы/события — дословно), критерии приёмки, что вне области. Если чего-то не знаешь — выясни, не додумывай.
2. **Plan.** Заполни `plan.md`: какие файлы меняются, какие решения принимаются, риски и обратная совместимость. Если решение трудно обратимо, неочевидно и является результатом трейд-оффа — заведи ADR в `docs/adr/`.
3. **Tasks.** Разбей на проверяемые пункты в `tasks.md` (чек-боксы), каждый — с командой проверки.
4. **Implement.** Меняй код, не расширяя объём за пределы спеки. Контракты — дословно из спеки.
5. **Verify.** Прогони проверки из спеки и общие (ниже), отметь задачи. Обнови документацию, если менялись контракты.

## Контекст для LLM (экономим токены)

- Начинай с `AGENTS.md` — там карта и инварианты.
- Читай только релевантный док: продукт → `SPEC.md`; система → `architecture.md`/`api.md`/`data.md`/`mcp.md`; грабли → `pitfalls.md`.
- Не пересказывай документацию в коде и комментариях — ссылайся на файл.

## Определение готовности

- Код компилируется: `npm run build` (web) и запуск затронутых сервисов.
- Контракт проверен способом из спеки: API — `curl` (см. `docs/api.md`), MCP — клиентский смоук (см. `docs/mcp.md`).
- Документация актуальна: обновлены `SPEC.md`/`architecture.md`/`api.md`/`data.md`/`mcp.md` при изменении контракта.
- Расхождения код ↔ док зафиксированы, а не замолчаны.

## Общие проверки

```bash
npm run build
curl http://localhost:3000/api/health
curl http://localhost:3000/api/filters
```

## Границы объёма

Не добавляй функции, которых нет в спеке; не «улучшай» то, что описано в `pitfalls.md` как намеренное; не меняй `data/`, `free-exercise-db/` и `.env`.

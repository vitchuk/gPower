# SPEC.md — продуктовая спецификация gPower

Источник истины о **продукте**. Если код и этот файл расходятся — это баг документации или кода, сообщи о расхождении, не догадывайся.

## Назначение

Мини-сервис поддержки пользователей на базе каталога упражнений: пользователь ищет упражнения в каталоге и задаёт вопросы ассистенту, который отвечает, опираясь на документацию каталога и данные о продукте.

Аудитория: русскоязычные пользователи; данные каталога — англоязычные (RU-резюме генерируются проектом).

## Роли

| Роль | Описание | Что доступно |
|---|---|---|
| Гость | неавторизованный посетитель | каталог, вкладка «Помощь» (чат без сохранения), FAQ |
| Пользователь | зарегистрированный владелец аккаунта | всё как у гостя + личные чаты с сохранением истории |

## Сценарии (с критериями приёмки)

**US-1. Найти упражнение.** Гость открывает каталог, задаёт фильтры (мышцы, снаряжение, уровень, усилие, тип, категория) и/или поиск, открывает карточку упражнения.
- *Приёмка*: фильтры применяются сразу; поиск понимает русские и английские запросы («грудь», «жим на грудь», «bench press»); результаты ранжированы по релевантности; карточка показывает мышцы, снаряжение, уровень и пошаговую технику.

**US-2. Зарегистрироваться и войти.** Гость создаёт аккаунт (логин ≥ 3, пароль ≥ 4 символов) и оказывается авторизованным.
- *Приёмка*: после регистрации сессия активна и сохраняется между перезагрузками; повторный вход работает; выход завершает сессию.

**US-3. Поговорить с ассистентом без входа.** Гость открывает вкладку «Помощь», читает FAQ, задаёт вопрос.
- *Приёмка*: ответ приходит потоком; цитаты-карточки показываются под ответом; история живёт только в браузере до перезагрузки.

**US-4. Вести личные чаты.** Пользователь открывает вкладку «Ассистент», создаёт чат, ведёт диалог, возвращается позже.
- *Приёмка*: чаты привязаны к пользователю; история и цитаты сохраняются в базе; заголовок чата автоматически берётся из первого сообщения.

**US-5. Спросить о продукте.** Пользователь спрашивает «Почему не работает авторизация?».
- *Приёмка*: ассистент вежливо даёт конкретные шаги диагностики (логин/пароль, cookie, запущен ли сервер, статус в Network, очистка данных сайта), а не отвечает «это не по моей части».

**US-6. Получить материалы по теме.** Пользователь просит подобрать упражнения.
- *Приёмка*: ассистент подбирает упражнения только из каталога; к ответу прикладываются цитаты-карточки с превью и ссылками.

## Нефункциональные требования

- **Локальный запуск**: вся система поднимается одной командой `npm run dev`; внешние зависимости — Ollama (эмбеддинги) и DeepSeek (LLM).
- **Экономия контекста**: RAG ограничивает контекст ответа топ-6 документами; история диалога — не более 10 сообщений; тем самым контролируются токены и стоимость LLM.
- **Приватность**: API-ключ только в `.env` (не в git); сессии — HttpOnly cookie.
- **Русский интерфейс**: подписи, FAQ и ответы ассистента — на русском; данные каталога — на английском.
- **Деградация**: при недоступной Ollama ассистент отвечает без RAG-контекста; при недоступном MCP — без инструментов; при отсутствии ключа LLM — понятная ошибка.
